# ADR 0003: 전역 입력 속도와 한글 키 순서 반응

- 날짜: 2026-11-07
- 상태: **Accepted — 사용자 추가 요구와 키 입력 순서 판정 확인 반영**
- 관련 문서: [요구사항](../product-requirements.md), [입력 계약](../input-and-keywords.md), [프로젝트 형식](../project-format.md)

## 결정

1. 캐릭터 앱·Studio에 포커스가 없어도 다른 일반 앱을 사용하는 동안 전역 키 입력·속도·특정 키·숨겨진 키워드 반응을 제공한다. 일반 입력 관찰을 전역 단축키 등록으로 대체하지 않는다.
2. 속도는 최근 2초의 non-repeat·non-modifier 물리 down 수를 2로 나눈 KPS다. 100 ms 평가·200 ms 구간 안정화·1000 ms 유휴 해제를 적용한다. 구간은 겹치지 않고 반복 애니메이션을 기본 상태로 선택한다.
3. 키워드는 실제 IME 확정 문자열이 아니라 **정해진 물리 키 입력 순서**로 판정한다. 한글은 ko-KR-2set, 영문은 en-US-qwerty 규칙으로 steps를 생성하며 직접 steps도 허용한다. Shift 상태를 포함하고 현재 한/영 모드·CapsLock과 독립적이다.
4. keySequence를 완료한 down과 특정 키·wildcard 후보를 한 번에 비교한다. 기본 상태는 속도→walk→idle이고 일회성 후보는 priority·정의 순서로 하나를 실행한다. 중단·재입력 규칙은 기존 반응과 같다.
5. Runtime은 KMP 접두 길이·마지막 적격 시각과 키 값 없는 속도 timestamp만 휘발성으로 유지한다. 입력 키 이력·다른 앱의 텍스트는 읽거나 저장하지 않는다. reset 후 패턴·속도를 복원하지 않는다.
6. 브라우저 확장·텍스트 브리지·별도 입력기·대상 앱 코드 삽입은 도입하지 않는다. 실제 텍스트와의 일치가 필요한 기능은 별도 후속 요구사항이다.

## 결과

한글을 이스터에그 이름으로 작성할 수 있으면서 동일한 전역 입력 계층을 유지한다. 다만 같은 물리 순서는 영문 입력 모드에서도 발동하며 두벌식 이외 자판·IME별 다른 조합법을 자동 추정하지 않는다. 제작 UI와 설치 안내에 이 의미를 명시한다. 두 OS의 전역 동작과 한글 변환 fixture를 M0~M3에서 검증하며 현재 구현 완료를 의미하지 않는다.

2026-11-07: Studio 제공 방식, 직접 드래그, 리소스 확장과 속도 타이밍 기본값은 [ADR 0004](0004-project-studio-and-media.md)로 대체한다. 위 결정의 이전 고정 타이밍·일정은 역사적 기록이다.
