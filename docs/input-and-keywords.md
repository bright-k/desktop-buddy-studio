# 전역 입력 속도와 키워드 계약

상태: 사용자 추가 요구·입력 순서 기준을 반영한 v1 계약, 실기 검증 전 / 기준일: 2026-11-07

## 1. 기본 동작과 지원 범위

캐릭터 앱·Studio에 포커스를 두지 않아도 **다른 앱에서 일반 작업을 하는 동안 전역 키 입력을 관찰**한다. 속도별 애니메이션·특정 키 반응·숨겨진 키워드 모두 같은 OS 입력 어댑터를 사용한다. 대상 앱에 코드를 삽입하거나 실제 입력란에 문자를 쓰지 않고 원래 입력을 차단·재전송하지 않는다.

사용자 확인에 따라 키워드의 판정 기준은 **정해진 물리 키 입력 순서**다. 한글 키워드는 제작 시 두벌식 키 순서로 변환한다. 예: `고양이` → `rhdiddl`에 해당하는 KeyR, KeyH, KeyD, KeyI, KeyD, KeyD, KeyL. 한글 IME의 실제 확정 문자열을 다른 앱에서 읽는 기능이 아니다. 현재 한/영 모드·CapsLock·자판 배치가 달라도 같은 물리 키와 Shift 순서면 발동한다. 화면에 표시되는 단어와의 일치까지 보장하지 않는다.

Windows 일반 사용자 데스크톱과 macOS 일반 사용자 세션이 지원 범위다. 보호된 입력·보안 데스크톱·권한 중단에서는 감지되지 않을 수 있으며 중단·복구 계약을 따른다. 별도 브라우저 확장·텍스트 브리지·손쉬운 사용 텍스트 읽기는 요구하지 않는다.

## 2. 입력 속도

- 단위는 **KPS(초당 물리 키 누름 수)**다. IME 완성 글자 수·단어 수가 아니다.
- 설정한 rateWindowMs(기본 2000 ms)의 정규 일반 키 최초 down 개수 N으로 `N * 1000 / rateWindowMs`를 계산한다. 창은 `(now - rateWindowMs, now]`다. modifier·Unknown·OS repeat·마우스는 제외한다. 유효한 키보드 감지 동안 매핑 유무와 무관하게 집계한다.
- 키 내용 없이 최대 2000개의 단조 timestamp만 메모리에 보관한다. 초과 시 집계를 reset하며 진단에는 횟수만 남긴다. RuntimeStatus.diagnostics는 세션의 epochResets·rateOverflowResets 수만 제공하고 키 값·타이핑 timestamp는 내보내지 않는다.
- 기본 50 ms 간격으로 구간을 평가하고 새 구간이 100 ms 연속 유지되면 전환한다. defaults.timing 및 앱 사용자 설정으로 평가·안정 시간을 조절한다. 전환 대기 중에는 기존 속도 애니메이션을 유지한다. 유효 구간이 없는 상태도 설정한 안정 시간 동안 지속되면 해제한다.
- 마지막 적격 down 이후 기본 250 ms(defaults.timing.idleTimeoutMs) 동안 새 입력이 없으면 대기 없이 속도 애니메이션·집계를 초기화한다. 다음 타이핑 묶음은 새로 시작한다.
- 기본 애니메이션은 **키 유지 sustain → 활성 속도 구간 → 실제 이동의 walk → idle** 순서다. 그 위에 특정 키·클릭·키워드의 일회성 반응이 표시된다. 속도 변경으로 일회성 반응을 중단하지 않는다. 직접 드래그하는 동안에는 drag 동작이 최우선이고 전역 입력은 중지한다.
- 편집·Player 설정·숨김·키보드 감지 중단·epoch 변경은 집계와 안정화 상태를 모두 reset한다. 재개 때 이전 속도를 복원하지 않는다.

제작 예시는 0.5~3 KPS에서 typing, 3 KPS 이상에서 typingFast다. 전 키 wildcard 일회성 반응을 함께 등록하면 그 반응이 속도 기본 애니메이션을 가릴 수 있으므로 Studio에서 이를 설명한다.

## 3. 키워드와 키 순서 정의

`keySequence`는 다음 둘 중 하나로 작성한다. 두 표현의 동시 사용은 검증 오류다.

| 표현 | 계약 |
| --- | --- |
| keyword + layout | keyword는 NFC 정규화 후 1~32 Unicode scalar. layout은 `ko-KR-2set` 또는 `en-US-qwerty`. 빌드 시 steps로 변환 |
| steps | 1~128개의 `{ code, shift }`. code는 정규 키 목록 중 modifier·Backspace·Delete를 제외한 값, shift는 필수 boolean |

keyword 입력은 현대 완성형 한글 음절 가~힣, ASCII 영문·숫자·일반 공백을 지원한다. en-US-qwerty에는 한글을 허용하지 않는다. 단독 자모·옛한글·이모지·구두점은 v1 keyword 변환에서 오류로 반환하고 필요한 경우 명시적 steps를 사용한다. 영문 대문자는 Shift=true, 소문자는 false이며 CapsLock은 고려하지 않는다. 숫자와 Space는 Shift=false다. 변환 후에도 최대 128 steps를 적용한다. timeoutMs는 정수 500~10000, 기본 5000이며 **인접한 적격 키 사이의 최대 시간**이다. 프로젝트당 sequence는 최대 32개이고 변환 후 동일한 steps 중복은 오류다.

두벌식 변환은 Unicode 현대 한글 음절을 초성·중성·종성으로 산술 분해한 뒤 아래 순서표로 치환한다. 표의 영문은 US QWERTY 물리 키를 뜻하며 대문자는 Shift=true다. 종성 없음은 빈 문자열이다. 이 변환은 Builder와 Studio가 같은 Project Core 함수를 사용하고, Runtime은 검증된 steps만 사용한다.

한글 음절 c는 `s = codePoint(c) - 0xAC00`, `초성 = s / 588`, `중성 = (s % 588) / 28`, `종성 = s % 28`로 분해한다. 나눗셈은 정수 나눗셈이며 19×21×28개의 현대 음절에만 적용한다. NFC와 분해 알고리즘 근거는 [참고 자료](references.md)에 둔다.

| 분류 | 자모 순서 | 대응 키 순서 |
| --- | --- | --- |
| 초성 | ㄱ ㄲ ㄴ ㄷ ㄸ ㄹ ㅁ ㅂ ㅃ ㅅ ㅆ ㅇ ㅈ ㅉ ㅊ ㅋ ㅌ ㅍ ㅎ | r R s e E f a q Q t T d w W c z x v g |
| 중성 | ㅏ ㅐ ㅑ ㅒ ㅓ ㅔ ㅕ ㅖ ㅗ ㅘ ㅙ ㅚ ㅛ ㅜ ㅝ ㅞ ㅟ ㅠ ㅡ ㅢ ㅣ | k o i O j p u P h hk ho hl y n nj np nl b m ml l |
| 종성 | 없음 ㄱ ㄲ ㄳ ㄴ ㄵ ㄶ ㄷ ㄹ ㄺ ㄻ ㄼ ㄽ ㄾ ㄿ ㅀ ㅁ ㅂ ㅄ ㅅ ㅆ ㅇ ㅈ ㅊ ㅋ ㅌ ㅍ ㅎ | 빈값 r R rt s sw sg e f fr fa fq ft fx fv fg a q qt t T d w c z x v g |

같은 자모를 반복 눌러 쌍자음을 만드는 등 IME별 다른 입력법은 자동 확장하지 않는다. 표의 표준 Shift 조합으로 매칭하며 다른 패턴은 별도 steps로 정의한다. 입력 모드나 실제 글자 조합을 추정하지 않는다.

## 4. 매칭·동작 충돌·초기화

1. 정규화한 non-repeat down만 matcher에 전달한다. Shift 자체는 소비하지 않고 현재 좌우 Shift의 합집합 상태를 각 step의 shift와 비교한다. native 재개 시 이미 눌린 modifier는 동작을 재생하지 않지만 현재 조합 상태에는 반영한다. 따라서 기존 Shift를 누른 채 새 키를 입력하면 Shift=true이며, 기존 Control·Alt·Meta를 누른 동안 sequence는 초기화한다. repeat·modifier-only 입력은 진행도와 timeout을 갱신하지 않는다.
2. Control·Alt·Meta 자체 down과 이들이 눌린 일반 키, Unknown, Backspace·Delete, 마우스 버튼 down은 모든 sequence의 진행도를 초기화한다. 일반 불일치는 KMP 접두 전이로 처리해 겹치는 접미부를 다음 시도의 시작으로 재사용한다. steps로 작성한 방향키·Enter·Tab 등은 일반 step으로 처리한다.
3. timeout 초과 후 다음 적격 down을 받으면 먼저 접두 길이를 0으로 만든다. 입력 순서는 OS 정규화 seq 기준이며 두 장치의 입력도 세션 순서로 합친다. 특정 앱의 문서나 입력란 경계는 추적하지 않는다. 따라서 클릭 없이 앱을 바꾼 경우에도 reset 키·timeout이 없다면 순서가 이어질 수 있다.
4. 한 down이 특정 키·wildcard·하나 이상의 완성 sequence를 동시에 만족하면 모든 일회성 후보를 합쳐 priority 내림차순·정의 순서 오름차순으로 하나만 선택한다. 예시의 키워드 priority=95는 Space=80보다 높다. 같은 입력에서 두 반응을 연달아 재생하지 않는다.
5. 완성 후 KMP의 겹치는 접두 상태를 유지해 다음 일치를 찾는다. 쿨다운·현재 우선순위로 실행이 거절돼도 매칭 진행 자체는 소비한다. matcher는 같은 입력을 재전송하거나 동작 대기열에 저장하지 않는다.
6. epoch reset·일시 정지·편집·설정·숨김·권한/감지 중단·종료 시 진행도와 timeout을 초기화한다. 재개 후 새 입력부터 시작하며 기존 prefix·눌린 키를 복원하지 않는다.

## 5. 데이터와 구현 경계

키워드 매칭은 등록 패턴과 패턴별 **KMP 접두 길이·마지막 적격 입력 시각**으로 처리한다. 입력한 키 목록·문자열·부분 문자열 이력을 저장하지 않는다. 속도 계산도 키 값 없는 timestamp만 휘발성으로 유지한다. 성능 계측을 위한 native 수신 시각은 제한된 입력 큐에서만 전달하고, 이후 동작 ID·FPS와 상관 처리해 집계한다. 입력 키나 개별 timestamp를 진단 파일로 내보내지 않는다. 설정에 들어 있는 키워드는 제작 데이터이며 앱 리소스 분석에 대한 비밀성을 보장하지 않는다. “숨겨진”은 일반 UI에 노출하지 않는 이스터에그라는 뜻이다.

로그·진단·빌드 보고서·일반 렌더러 IPC에 실제 키 입력·순서·입력 이력을 남기지 않는다. 화면에는 선택된 애니메이션·방향·속도 구간 ID만 전달한다. Studio의 테스트 패널은 제작자가 직접 누른 모의 입력과 매칭 결과를 보여주며 전역 입력 이력을 기록하는 디버거를 제공하지 않는다.

사용자 토글은 input.keyboard 하나가 물리 키·속도·sequence를 함께 제어한다. 감지 가능한 키의 범위, 눌림 복구와 사용자 상태는 [아키텍처](architecture.md)를 따른다.

## 6. 필수 검증

- 다른 텍스트 편집기·브라우저·일반 업무 앱이 전경일 때 캐릭터 앱 포커스 없이 세 가지 반응을 시험한다. 해당 앱의 문자 입력·단축키가 그대로 동작해야 한다.
- KPS 창 경계, 설정 가능한 안정화·유휴, 반복 키 제외, 구간 겹침 거부를 모의 시계로 검증한다.
- `고양이`, 쌍자음·복합모음·겹받침 키워드의 변환 fixture와 명시적 steps의 동등성을 검사한다. 잘못된 layout·지원하지 않는 문자·128 step 초과는 빌드 실패다.
- 한글/영문 입력 모드를 바꿔도 같은 물리 순서가 발동하며, 잘못된 순서·Shift·Backspace·Control 조합·timeout은 발동하지 않는다. 다른 IME 조합법을 정답으로 자동 인정하지 않는다.
- 특정 키·keyword 최종 키·wildcard의 동시 후보, 겹치는 패턴, 쿨다운 거절, pause/resume reset, 두 앱 동시 감지를 검사한다. OS별 실제 입력 시험은 별도로 수행한다.
