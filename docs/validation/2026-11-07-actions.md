Actions 회귀는 실제 CLI snapshot·검증한 템플릿 팩과 제어된 GitHub 응답으로 다음을 검사한다.

- 연결·워크플로 준비·고정 엔진/참조 파일 전송, 미참조 편집·인증 제외.
- 같은 요청의 동시 클릭 재사용, 다른 저장소로 연결이 바뀐 요청 거부.
- dispatch 응답 유실 후 기존 실행 복구, 재시작 후 중복 dispatch 방지.
- 인증 만료 후 연결 대기·재연결 복구, 취소의 202 빈 응답 처리.
- 원격 commit 불일치 거부, 부분 성공 보존·가져오기 실패 재시도.
- digest·CRC·허용 ZIP 파일명·tar/PAX 긴 경로·설치 파일 SHA-256 검사와 AppleDouble metadata 처리.
- artifact 리디렉션에 인증 미전달, 외부 호스트 거부, 연결 HTTP의 세션·Origin 검사와 토큰 비노출.

## 발견하고 수정한 Windows 빌더 문제

첫 실행 42338977829에서 Node CLI가 Rust의 verbatim 드라이브 경로를 읽지 못해 아이콘 생성이 실패했다. 외부 도구용 canonical 경로를 일반 drive/UNC 표현으로 바꿨다.

두 번째 실행 42339331610에서는 아이콘·웹 생성 후 MSVC linker가 긴 출력 파일명을 열지 못했다. 최종 프로젝트 출력은 유지하고 중간 Cargo 캐시를 짧은 임시 루트 아래에 엔진·target·출력 identity hash로 격리했다. Windows 전용 Node 경로 회귀와 각 OS의 builder 계약 검사를 workflow에 추가했다.

세 번째 실행 42339804805는 Windows 앱·NSIS 설치 파일과 정적 검사를 통과했지만 Git Bash의 GNU tar가 드라이브 문자를 원격 host로 해석해 최종 묶음 생성에서 실패했다. Windows 기본 System32/tar.exe를 명시해 프로젝트 내보내기·CI 결과 묶음 모두 같은 경로 규칙을 사용한다.

실행 앱의 키보드/마우스 권한·트레이·드래그, Windows 설치/업데이트/제거, macOS 정식 지원 하한·외부 다운로드·공개 서명/공증은 이번 빌드 검증과 별도이며 통과로 표시하지 않는다. 현재 실행 중인 이전 Typing Cat 앱과 입력 권한은 변경하지 않았다.
