# Studio 사용성 검토와 개선

기준일: 2026-11-07. 프로젝트 생성 → 리소스·동작 편집 → 검증 → 미리보기 → 빌드, 새로고침·프로젝트 전환·오류 복구 흐름을 검토했다.

| 발견한 문제 | 반영한 개선 |
| --- | --- |
| UUID 폴더와 주소로는 프로젝트를 식별하기 어려움 | 패키지 ID를 폴더·API·URL의 공통 키로 사용. 생성 화면에서 직접 지정하며 기존 UUID 주소는 자동 연결 |
| 저장 전 새로고침·프로젝트 이동 시 편집을 잃을 수 있음 | 프로젝트별 draft.json에 임시 편집 자동 보관. 재진입 시 복원하고 저장한 구성과 구분. 다른 탭의 임시 편집은 덮어쓰지 않음 |
| 수정했는데 미리보기가 바뀌지 않아 혼동 | 저장된 버전임을 표시하고 변경 중에는 ‘저장하고 미리보기’ 제공 |
| 긴 편집 화면에서 저장 버튼이 사라짐 | 상단 도구 모음 고정, Cmd/Ctrl+S, 변경 없는 상태의 저장 비활성화, 변경 취소 제공 |
| 오류가 짧게 뜨는 알림에만 표시됨 | 지속되는 오류 패널, 관련 탭·동작으로 이동, 흔한 오류의 한국어 안내, 현재 편집 JSON 백업 |
| 파일 하나가 잘못되면 여러 파일 가져오기 전체가 멈춤 | 파일별 처리와 성공·실패 요약, 16 MiB 사전 검사, 중복 리소스 참조 방지 |
| 작은 GIF·큰 스프라이트가 설명을 덮음 | 확정된 이미지 영역 안에 비율 유지·잘림 처리. 메타데이터를 독립 행으로 배치 |
| 좁은 화면에서 미리보기 캔버스가 찌그러질 수 있음 | 캔버스 종횡비 유지, 작은 화면의 저장 상태 표시·버튼 줄바꿈 |
| 연속 빌드 클릭으로 같은 작업이 중복될 수 있음 | 같은 프로젝트·저장 버전·모드의 대기/진행 작업 재사용 |
| 빌드 이력 새로고침이 로그 열림·스크롤을 초기화함 | 변경된 작업만 다시 표시하고 로그 열림·읽던 위치 보존 |
| 프로젝트를 빠르게 바꾸면 오래된 응답이 덮을 수 있음 | 최신 요청만 반영하고 로딩 중 편집 영역 잠금. 상태를 브라우저 제목에도 표시 |
| 빌드 버튼만 보면 다른 OS도 동시에 생성되는지 알 수 없음 | 상단 버튼은 빌드 화면으로 이동. 연결·공개 여부·업로드 범위를 표시하고 두 플랫폼 Actions 빌드를 제공. 로컬 빌드는 별도로 선택 |
| Actions 결과를 찾아 따로 내려받아야 함 | 플랫폼별 단계·취소·상세 로그 링크·자동 결과 가져오기. 일부 성공 보존과 가져오기 재시도 제공 |
| 설정에서 입력을 꺼놓고 테스트하면 고장으로 보임 | 꺼진 입력·이동 기능을 테스트할 때 해당 설정을 안내 |

임시 편집은 아직 앱 구성에 반영되지 않은 작업 내용이다. ‘저장’은 검증한 새 revision을 만들고 미리보기를 갱신한다. ‘앱 빌드’는 저장된 revision을 사용한다. 임시 편집 취소·정식 저장 시 이전 draft도 프로젝트의 drafts 폴더에 보관한다.

자동 검증은 draft 재시작 복원·다른 창 충돌·정식 저장 분리, 중복 빌드 방지, 패키지 ID 충돌·중단된 이전 복구·기존 다운로드 호환을 포함한다. 브라우저에서는 패키지 ID 생성, 이전 UUID 주소 연결, 임시 편집 후 새로고침 복원, Cmd+S, 잘못된 FPS 안내, 정상·손상 이미지 동시 가져오기, 저장 후 GIF 미리보기와 연속 빌드 클릭을 확인했다. 실제 전역 입력·트레이·버디 드래그의 네이티브 실기는 사용자가 직접 확인하며 웹 검증과 구분한다.


## Player와 Studio 후속 검토

| 사용 흐름 | 반영한 개선 |
| --- | --- |
| 설정을 열었을 때 버디가 반응하지 않음 | 창 상단에 설정 중 감지 중지·일시 정지·숨김·드래그 상태를 표시하고, 저장된 소스 설정과 권한 상태를 따로 표시 |
| 설정을 스크롤하거나 실수로 닫음 | 하단에 저장 상태와 저장·저장하고 닫기 고정. Cmd/Ctrl+S, Esc 및 창 닫기에서 변경 보존. 미저장 시 저장·버리기·계속 편집 선택 |
| 드래그와 설정 편집이 겹침 | 설정 창을 유지하고 저장된 위치와 트레이 상태를 갱신. 바꾼 필드만 적용하고 실제 제한된 위치를 저장 뒤 표시 |
| 버디 클릭을 드래그로 처리하거나 입력이 밀림 | 작은 포인터 흔들림은 무시. 이동을 묶어 처리하고 포인터 취소는 기존 위치로 복귀. 시작 명령의 overlay 권한을 등록 |
| 리소스와 이벤트 사이에서 사용처를 찾기 어려움 | 리소스 → 사용 동작 → 연결 이벤트 링크와 URL 탐색 이력. 새로고침·뒤로/앞으로 가기에서 선택 복원 |
| 빠른 미리보기 전환 시 이전 결과가 다시 표시됨 | 다른 미리보기 실행·재생·페이지 변경 뒤 늦은 응답을 무시 |
| Studio 서비스 종료나 세션 만료를 알아차리기 어려움 | 연결 상태를 지속 표시하고 편집 JSON 내보내기·연결 재시도 제공 |
| 설치 파일을 로그·보고서 사이에서 찾아야 함 | OS별 설치 파일 강조, 기타 파일과 로그는 접어서 표시. 실행 중 단계와 실패 단계 표시, 진행 갱신 시 펼침과 로그 위치 유지 |
| 업로드가 끝날 때까지 빌드 취소가 지연됨 | 취소를 개별 작업에 먼저 저장하고 실행 요청 전에 확인. 이미 실행 요청이 나갔다면 기존 실행을 찾아 취소 |

자동 검사에서 설정 변경 병합, 드래그 임계값·이동 병합·취소, 업로드 도중 취소 후 미실행을 확인했다. 브라우저에서 실제 Studio의 모바일 리소스 배치, 리소스에서 이벤트까지 탐색, URL 복원, 미리보기, 플랫폼별 설치 파일, 연결 종료·세션 만료 후 재접속을 확인했다. Player 설정 화면은 480 × 560의 모의 호스트로 확인했다. Mac 개발용 패키지를 빌드해 정적 검증했고 전역 입력 권한·트레이·네이티브 창과 Windows 실기는 별도다.

## 저장과 복원 반복 검증

| 검증 조건 | 수정 후 확인한 결과 |
| --- | --- |
| 프로젝트를 바꾸는 동안 임시 저장 응답을 지연 | 편집 영역이 먼저 잠기고, 돌아오면 전환 직전의 편집이 복원된다. |
| 저장 성공 뒤 프로젝트 목록 조회 실패 | 새 버전 응답으로 화면과 목록을 갱신하고 저장 성공 상태를 표시한다. |
| 프로젝트 읽기 도중 다른 요청이 새 버전을 저장 | 메타데이터, 구성과 미리보기는 한 저장 버전을 기준으로 읽는다. |
| 미리보기 파일을 쓸 수 없는 상태에서 저장 | 이전 저장 버전과 임시 편집이 남고, 파일 쓰기가 복구되면 같은 편집을 저장할 수 있다. |
| 다른 창에서 새 임시 편집을 저장한 뒤 이전 버전 복원 | 복원 요청이 오래된 경우 충돌을 알린다. 확인한 편집은 보관하며 이후 버전을 오가도 자동으로 다시 나타나지 않는다. |
| 위치를 저장할 수 없는 상태에서 버디를 드래그 | 이전 위치로 돌아가고 드래그 세션을 종료한다. 설정 창에서 저장 실패 원인을 확인할 수 있다. |

Studio의 전환과 저장 오류는 격리된 프로젝트와 로컬 서버에서 재현했다. Chrome에서 복원 확인창의 취소와 확정까지 확인하고, 확정 뒤 임시 편집 보관 파일을 검사했다. 앱의 드래그 오류는 실제 설정 저장 로직을 읽기 전용 상태로 실행해 확인했다.
