# 제품 요구사항

상태: 사용자 요구와 위임된 상세 결정을 반영한 v1 구현 기준 / 기준일: 2026-11-07

## 1. 제품 목표와 범위

제작자가 설정 파일과 캐릭터 리소스를 정의하면, 공통 코드를 수정하지 않고 여러 독립 실행 데스크톱 앱을 만들 수 있어야 한다. 예시는 타이핑에 반응하는 고양이, 클릭에 반응하는 마스코트, 방향키로 움직이는 캐릭터다.

최초 범위는 입력 반응형 데스크톱 캐릭터·위젯 프로그램이다. 임의의 업무 앱을 생성하는 범용 앱 빌더, 사용자 스크립트 실행, 웹 서비스 제작까지 확장하지 않는다.

| 사용자 | 해야 할 일 |
| --- | --- |
| 최초 제작자 | CLI·JSON·로컬 도구체인으로 프로젝트 생성·복제, 이미지·동작 정의, 미리보기, OS별 앱 빌드 |
| 배포받은 사용자 | 제작 도구 없이 앱 설치·실행, OS 승인, 위치·배율 조정, 일시 정지·종료 |
| Studio 개발자 | 공통 런타임과 스키마를 개선하고 기존 프로젝트 호환성 유지 |

## 2. 사용자 확정 사항과 위임된 v1 결정

**사용자 확정**: Tauri + Rust, Windows·Mac, 위치·크기·키보드·마우스, 여러 설정·리소스에서 독립 앱 빌드, 공식 서명·공증 불필수, 필요시 셀프 서명 허용. 캐릭터 앱에 포커스가 없어도 일반적인 다른 작업 중 전역 입력에 반응해야 한다. 입력 속도·특정 키·숨겨진 키워드별 애니메이션을 지원하며, 한글 키워드도 사용자가 확인한 **물리 키 입력 순서**를 기준으로 판정한다.

**사용자 위임으로 구체화한 v1 결정**: TypeScript + Vite + Canvas 2D, 최초에는 별도 UI 프레임워크 없음, 선언형 JSON, Builder CLI + 로컬 웹 Studio, 로컬 OS별 빌드, 프로젝트당 캐릭터 1개, Windows 11 25H2 이상 x64·macOS 15 이상 arm64. 동작·상태·Builder 계약은 [ADR 0002](decisions/0002-runtime-and-builder-contracts.md), 속도·한글 키 순서 판정은 [입력 계약](input-and-keywords.md)에 둔다. 실제 플랫폼 검증은 별도다.

## 3. 사용자 흐름

### 제작

1. 기본 프로젝트를 만들거나 기존 프로젝트를 복제한다.
2. 제품 이름·앱 식별자·버전·아이콘을 지정한다. 복제 시 새 식별자를 제안한다.
3. 캐릭터 PNG/JPEG/GIF/정적 WebP/BMP와 스프라이트 영역, 입력 속도 구간·특정 키·한글/영문 키워드와 애니메이션, 유지 이동의 walk를 설정한다.
4. 검증 오류를 수정하고 공통 Runtime으로 미리 본다.
5. 대상 OS·CPU를 선택해 빌드한다. 현재 컴퓨터에서 불가능한 대상은 사유를 표시한다.
6. 설치 파일과 설치·권한 안내를 배포한다. 빌드 성공과 외부 컴퓨터 실행 검증은 별도로 표시한다.

### 설치·실행

1. 사용자가 설치 또는 앱 복사를 수행한다.
2. OS가 표시하는 실행 신뢰 경고를 해당 OS의 사용자 승인 흐름에서 처리한다.
3. 첫 실행 안내에서 필요한 입력 감지 권한을 사용자가 허용한다.
4. 권한이 없으면 캐릭터 표시와 설정은 유지하며 입력 반응만 비활성화한다.
5. 다른 앱에서 일반 작업을 하며 캐릭터 앱 포커스 없이 입력 반응을 사용한다. 한글 키워드는 지정한 두벌식 물리 키 순서로 발동하며 현재 한/영 모드와 독립적이다.
6. 화면의 버디를 바로 드래그해 위치를 저장하고 크기는 설정에서 바꾼다. 드래그·Player 설정 중에는 전역 입력 반응을 중지하며 드래그 전용 동작을 지정할 수 있다.

OS 실행 승인, 설치 경로 권한, 입력 모니터링은 서로 다른 상태다. 설치기가 입력 권한을 미리 일괄 허용한다고 가정하지 않는다. 자세한 플랫폼 근거는 [빌드·배포](build-and-distribution.md)에 둔다.

## 4. 기능 요구사항

P0는 Builder + Runtime + 로컬 웹 Studio이며 플랫폼 출시는 지원 OS 실기 검증을 별도로 통과해야 한다. [ADR 0004](decisions/0004-project-studio-and-media.md)가 추가 계약이다.

| ID | 우선순위 | 요구사항과 완료 기준 |
| --- | --- | --- |
| B01 | P0 | 프로젝트 검증: 잘못된 필드·자산 경로·동작 참조를 파일과 JSON 경로를 포함한 오류로 반환한다. 실패하면 빌드하지 않는다. |
| B02 | P0 | 여러 프로젝트 빌드: 서로 다른 이름·아이콘·식별자·리소스·입력을 가진 두 앱을 공통 코드 수정 없이 생성한다. |
| B03 | P0 | 독립 실행: 생성 앱은 Studio·Builder·Node.js·Rust가 없는 배포 대상 컴퓨터에서 동작한다. OS WebView 의존성은 설치 안내에 명시한다. |
| B04 | P0 | 플랫폼 빌드: Windows x64와 macOS arm64 앱을 각 OS의 빌드 환경에서 만든다. macOS x64는 별도 검증 후 지원한다. |
| B05 | P0 | 빌드 작업 관리: 진행·취소·오류·산출물·보고서를 제공한다. 사전 검사 후 snapshot을 만들고 snapshot을 최종 검증·hash 확정한 뒤 빌드한다. 복사 중 변경은 실패하며 미완성 파일을 성공으로 표시하지 않는다. |
| B06 | P0 | 리소스 패키징: 실행에 필요한 이미지·설정을 앱 내부에 포함하고 원본 프로젝트 절대 경로에 의존하지 않는다. |
| B07 | P0 | 배포: Windows 사용자 단위 설치 파일과 macOS 앱/DMG, 해시·버전·권한 안내를 생성한다. 공식 인증서 없이 가능해야 한다. |
| B08 | P0 | 앱 분리: 서로 다른 앱은 사용자 설정·단일 인스턴스 잠금·제거 항목을 분리하고 동시에 실행된다. |
| B09 | P0 | Builder 배포: 원래 저장소 checkout 없이 OS별 CLI 릴리스와 동봉 템플릿 팩으로 빌드한다. 필요한 Player·공통 소스·잠금 파일을 작업 디렉토리 안에 구성한다. 로컬 도구체인은 doctor로 진단한다. |
| R01 | P0 | 표시: 투명·무테·항상 위 표시를 제공하고 일반 모드에서 다른 앱의 키보드 포커스를 빼앗지 않는다. |
| R02 | P0 | 위치: 편집 드래그·좌표·모니터 선택·완료/취소·위치 초기화 제공. 기본 배치를 저장하고 자동 이동 좌표는 세션에만 둔다. 재시작은 기본 배치, 모니터 제거는 보이는 위치로 복구한다. |
| R03 | P0 | 크기: 25~300% 배율을 제공하되 모니터 작업 영역에 맞춰 상한을 제한한다. 배율 변경 후 캐릭터가 잘리지 않는다. |
| R04 | P0 | 직접 드래그: 보이는 버디를 눌러 바로 이동하고 놓으면 저장한다. 투명 영역의 클릭은 뒤쪽 앱으로 통과하며, 화면 가장자리에서는 대기 동작의 보이는 범위를 기준으로 위치를 제한한다. 크기는 설정에서 변경한다. |
| R05 | P0 | 키보드: 캐릭터 앱·Studio 포커스 없이 다른 일반 앱이 전경인 동안 전역 down/up·modifier·동시 입력을 관찰한다. 특정 키별 애니메이션을 정의하고 원래 앱의 입력을 차단·재전송하지 않는다. |
| R06 | P0 | 마우스: 전역 위치·버튼 down/up·휠을 관찰한다. 이동 이벤트는 병합하고 클릭·키 전이는 순서를 유지한다. |
| R07 | P0 | 행동: 기본 속도/walk/idle과 일회성 반응을 분리한다. move.animation으로 유지 이동·걷기를 연결하고 일회성 loop는 금지한다. Rust가 종료·중단을 판정하며 중단 반응은 재개하지 않는다. |
| R08 | P0 | 관리: 트레이에 실제 감지 상태·체크형 표시/숨김·전체 입력 일시 정지·소스별 토글·설정·위치/전체 설정 초기화·종료를 제공한다. 드래그·설정·숨김 중 전역 입력 동작은 중지한다. |
| R09 | P0 | 권한: 사용자 입력 토글·소스별 OS 권한·실제 감지 상태를 분리한다. 거부 시 반복 팝업 없이 안내·재시도하며 숨김과 권한 중단이 사용자 토글을 바꾸지 않는다. |
| R10 | P0 | 복구: 절전·잠금·장치 제거·보안 입력·감지 중단·재개 시 epoch와 held·속도·sequence·반응을 초기화한다. 키 해제 누락·이전 큐 재생으로 이동이나 키워드가 이어지지 않는다. |
| R11 | P0 | 설정: 앱별 명시적 override를 원자적으로 저장·백업한다. 자동 이동은 쓰지 않는다. 손상·저장 실패·미래 버전 복구 및 입력 off의 전체 초기화를 제공하며 원본을 보존한다. |
| R12 | P0 | 입력 속도: 전역 non-repeat 일반 키의 설정한 창(기본 2초) KPS로 서로 겹치지 않는 구간별 반복 애니메이션을 선택한다. 기본 50 ms 평가·100 ms 안정화·250 ms 유휴 해제를 적용한다. 프로젝트·사용자 설정으로 조절하며 pause/reset 후 과거 속도를 복원하지 않는다. |
| R13 | P0 | 키워드: 영문·한글 keyword를 선언한 QWERTY/두벌식 물리 steps로 변환하거나 steps를 직접 정의한다. 전역 순서·Shift·timeout을 검사해 다른 애니메이션을 재생한다. 실제 IME 텍스트 읽기·대상 앱 입력 없이 동작하고 입력 이력을 남기지 않는다. |
| S01 | P0 | Studio: 프로젝트 생성·복제·열기·저장과 최근 프로젝트를 제공한다. 파일 직접 편집과 같은 스키마를 사용한다. |
| S02 | P0 | 편집: 리소스·애니메이션·속도 구간·특정 키·키워드·이동·제품 정보를 폼으로 편집한다. 명시적 steps는 JSON/CLI에서 지원한다. 로컬 빌드와 연결한 GitHub Actions 빌드를 선택한다. |
| S03 | P0 | 미리보기: 실제 앱과 같은 Runtime 규칙을 사용한다. 웹에서는 모의 입력을 사용하고, 네이티브 전역 입력은 빌드된 Player의 사용자 설정과 권한으로 검증한다. |
| S04 | P0 | GUI 빌드: Builder의 검증·진행·취소·결과를 GUI로 제공하고 별도의 빌드 로직을 만들지 않는다. |
| S05 | 추가 요구 | GitHub Actions: 저장소 연결·workflow 준비·고정 snapshot/엔진 업로드·두 OS 빌드·진행/취소·검증한 결과의 프로젝트별 보관을 제공한다. 인증은 브라우저/프로젝트에 저장하지 않고 공개 저장소 업로드 범위를 표시한다. 중복 요청·재시작·부분 성공·가져오기 재시도 계약은 [Actions 연동 안내](studio-actions.md)를 따른다. |

## 5. 비기능 요구사항

아래 수치는 측정 결과가 아니라 **최초 목표값**이다. 기준 기기와 측정 방법은 [검증 전략](testing-strategy.md)에 고정한다.

| ID | 목표 |
| --- | --- |
| N01 | 기본팩 1개·설정 창 닫힘 기준, Runtime과 귀속 가능한 자식 프로세스 메모리 합계 200 MiB 이하를 목표로 한다. OS별 지표를 별도로 보고한다. |
| N02 | 애니메이션 없는 유휴 CPU 평균은 1개 논리 코어 대비 1% 이하, 기본팩 30 FPS 재생은 5% 이하를 목표로 한다. GPU·전력도 별도로 측정한다. |
| N03 | 입력 콜백 수신부터 렌더러 프레임 처리 ACK까지 p95 80 ms 이하를 목표로 한다. 이는 실제 화면 발광 지연 측정이 아니다. |
| N04 | 준비된 OS WebView 환경에서 앱 콜드 스타트부터 캐릭터 표시까지 2.5초 이하를 목표로 한다. 최초 빌드 시간은 별도 측정한다. |
| N05 | 잠금 파일과 도구체인·템플릿 버전을 기록하고 동일 입력의 논리적 빌드 재현성을 확보한다. 서명·패키지 타임스탬프까지 동일한 바이트 재현성을 보장하지는 않는다. |
| N06 | 프로젝트는 데이터만 포함한다. 임의 스크립트·셸 명령·네이티브 플러그인을 가져와 실행하지 않는다. |
| N07 | 실제 키·문자 원문·입력 이력을 파일·로그·네트워크·렌더러 IPC에 저장/전송하지 않는다. 속도용 키 값 없는 2초 timestamp와 sequence 접두 길이만 휘발성으로 유지·reset한다. 다른 앱의 텍스트는 읽지 않는다. 일반 실행에 서버 연결은 필요하지 않다. |
| N08 | 설치·실행·권한 안내를 제공하고, 공식 서명·공증 없이 가능한 범위와 OS 정책상 차단을 구분한다. |
| N09 | 두 독립 앱 동시 실행에서 각 앱의 N01~N04를 유지하고 합계 자원·전력도 보고한다. 5개 동시 실행은 확대 측정이며 최초 지원 보장은 2개다. |
| N10 | release CSP·자산 scope·창별 명령 허용 목록을 명시하고 Player에 프로젝트 편집·빌드·임의 셸 권한을 포함하지 않는다. |

## 6. 범위 이후

복수 캐릭터 배치, 레이어·Live2D·3D, 자유 스크립트·범용 effect 배열·노드 그래프, 자동 업데이트, 스토어 등록, Linux·Windows ARM64는 초기 범위 밖이다. GitHub Actions 원격 빌드는 사용자 추가 요구 S05로 도입한다. 실제 IME 확정 문자열 판독·앱별 입력 제외·시작프로그램 등록·사용자용 동작 감소/저전력 프리셋은 후속 범위다. 한 앱에 여러 캐릭터와 여러 독립 앱 생성은 별도 요구사항이다.

## 7. 제품 완료 기준

- 서로 다른 두 프로젝트에서 별도 앱을 생성한다.
- 각 지원 OS의 제작 도구 없는 컴퓨터에서 다운로드·설치·권한·실행 흐름을 검증한다.
- A 앱의 위치·설정 변경이나 제거가 B 앱에 영향을 주지 않는다.
- 설정·리소스만 수정한 프로젝트에서 다른 입력 반응이 만들어진다.
- 다른 앱의 일반 작업 중 포커스 없이 특정 키·KPS·한글 키 순서 키워드 반응이 동작하고 원래 입력은 유지된다.
- 원래 저장소가 없는 제작 환경에서도 배포된 CLI·템플릿 팩·로컬 도구체인으로 빌드된다.
- 공식 인증서·공증 자격증명 없이 릴리스 산출물이 만들어진다.
- 대상 OS별 제약, 실제 검증 여부와 미검증 항목이 릴리스 보고서에 남는다.
