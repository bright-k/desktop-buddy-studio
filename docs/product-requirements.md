# 제품 요구사항

상태: 사용자 확정 방향을 반영한 구현 전 초안 / 기준일: 2026-11-07

## 1. 제품 목표와 범위

제작자가 설정 파일과 캐릭터 리소스를 정의하면, 공통 코드를 수정하지 않고 여러 독립 실행 데스크톱 앱을 만들 수 있어야 한다. 예시는 타이핑에 반응하는 고양이, 클릭에 반응하는 마스코트, 방향키로 움직이는 캐릭터다.

최초 범위는 입력 반응형 데스크톱 캐릭터·위젯 프로그램이다. 임의의 업무 앱을 생성하는 범용 앱 빌더, 사용자 스크립트 실행, 웹 서비스 제작까지 확장하지 않는다.

| 사용자 | 해야 할 일 |
| --- | --- |
| 제작자 | 프로젝트 생성·복제, 이미지·동작 정의, 미리보기, 대상 OS 앱 빌드 |
| 배포받은 사용자 | 제작 도구 없이 앱 설치·실행, OS 승인, 위치·배율 조정, 일시 정지·종료 |
| Studio 개발자 | 공통 런타임과 스키마를 개선하고 기존 프로젝트 호환성 유지 |

## 2. 확정 사항과 설계 제안

**사용자 확정**: Tauri + Rust, Windows·Mac, 위치·크기·키보드·마우스, 여러 설정·리소스에서 독립 앱 빌드, 공식 서명·공증 불필수, 필요시 셀프 서명 허용.

**설계 제안**: WebView UI는 TypeScript + Vite, 최초 캐릭터 렌더러는 Canvas 2D, 선언형 JSON 프로젝트, Builder CLI 우선 개발 후 Studio GUI 추가, 로컬 OS별 빌드, 최초 프로젝트당 캐릭터 1개.

## 3. 사용자 흐름

### 제작

1. 기본 프로젝트를 만들거나 기존 프로젝트를 복제한다.
2. 제품 이름·앱 식별자·버전·아이콘을 지정한다. 복제 시 새 식별자를 제안한다.
3. 캐릭터 PNG 시트와 애니메이션, 입력과 행동의 연결을 설정한다.
4. 검증 오류를 수정하고 공통 Runtime으로 미리 본다.
5. 대상 OS·CPU를 선택해 빌드한다. 현재 컴퓨터에서 불가능한 대상은 사유를 표시한다.
6. 설치 파일과 설치·권한 안내를 배포한다. 빌드 성공과 외부 컴퓨터 실행 검증은 별도로 표시한다.

### 설치·실행

1. 사용자가 설치 또는 앱 복사를 수행한다.
2. OS가 표시하는 실행 신뢰 경고를 해당 OS의 사용자 승인 흐름에서 처리한다.
3. 첫 실행 안내에서 필요한 입력 감지 권한을 사용자가 허용한다.
4. 권한이 없으면 캐릭터 표시와 설정은 유지하며 입력 반응만 비활성화한다.
5. 트레이에서 편집 모드로 들어가 위치·크기를 바꾸고 표시 모드로 돌아간다.

OS 실행 승인, 설치 경로 권한, 입력 모니터링은 서로 다른 상태다. 설치기가 입력 권한을 미리 일괄 허용한다고 가정하지 않는다. 자세한 플랫폼 근거는 [빌드·배포](build-and-distribution.md)에 둔다.

## 4. 기능 요구사항

P0는 최초 배포 가능한 Builder + Runtime MVP, P1은 Studio 및 후속 편의 기능이다.

| ID | 우선순위 | 요구사항과 완료 기준 |
| --- | --- | --- |
| B01 | P0 | 프로젝트 검증: 잘못된 필드·자산 경로·동작 참조를 파일과 JSON 경로를 포함한 오류로 반환한다. 실패하면 빌드하지 않는다. |
| B02 | P0 | 여러 프로젝트 빌드: 서로 다른 이름·아이콘·식별자·리소스·입력을 가진 두 앱을 공통 코드 수정 없이 생성한다. |
| B03 | P0 | 독립 실행: 생성 앱은 Studio·Builder·Node.js·Rust가 없는 배포 대상 컴퓨터에서 동작한다. OS WebView 의존성은 설치 안내에 명시한다. |
| B04 | P0 | 플랫폼 빌드: Windows x64와 macOS arm64 앱을 각 OS의 빌드 환경에서 만든다. macOS x64는 별도 검증 후 지원한다. |
| B05 | P0 | 빌드 작업 관리: 진행 단계·취소·오류 원인·산출물 경로·빌드 보고서를 제공한다. 실패한 중간 파일을 성공 산출물로 표시하지 않는다. |
| B06 | P0 | 리소스 패키징: 실행에 필요한 이미지·설정을 앱 내부에 포함하고 원본 프로젝트 절대 경로에 의존하지 않는다. |
| B07 | P0 | 배포: Windows 사용자 단위 설치 파일과 macOS 앱/DMG, 해시·버전·권한 안내를 생성한다. 공식 인증서 없이 가능해야 한다. |
| B08 | P0 | 앱 분리: 서로 다른 앱은 사용자 설정·단일 인스턴스 잠금·제거 항목을 분리하고 동시에 실행된다. |
| R01 | P0 | 표시: 투명·무테·항상 위 표시를 제공하고 일반 모드에서 다른 앱의 키보드 포커스를 빼앗지 않는다. |
| R02 | P0 | 위치: 편집 모드 드래그·좌표 입력·모니터 선택·재시작 복원을 제공한다. 모니터 제거 시 보이는 위치로 복구한다. |
| R03 | P0 | 크기: 25~300% 배율을 제공하되 모니터 작업 영역에 맞춰 상한을 제한한다. 배율 변경 후 캐릭터가 잘리지 않는다. |
| R04 | P0 | 클릭 통과: 표시 모드에서는 전체 오버레이를 통과하고 편집 모드에서만 드래그를 받는다. 트레이로 언제든 복구할 수 있다. |
| R05 | P0 | 키보드: 백그라운드 key down/up·modifier·동시 입력을 관찰한다. 감지만 수행하며 원래 앱의 입력을 차단하거나 재전송하지 않는다. |
| R06 | P0 | 마우스: 전역 위치·버튼 down/up·휠을 관찰한다. 이동 이벤트는 병합하고 클릭·키 전이는 순서를 유지한다. |
| R07 | P0 | 행동: 애니메이션 재생과 화면 위치 이동을 별도 행동으로 지원한다. 우선순위·재입력·유휴 복귀 규칙을 정의한다. |
| R08 | P0 | 관리: 트레이에서 표시/숨김, 입력 감지 켜기/끄기, 편집, 설정, 종료를 제공한다. |
| R09 | P0 | 권한: 필요·허용·거부·중단 상태를 구분한다. 거부 시 반복 팝업 없이 안내하고 사용자가 다시 시도할 수 있다. |
| R10 | P0 | 복구: 절전·잠금·입력 감지 중단 시 눌린 키 상태를 초기화해 이동이 계속되는 현상을 방지한다. |
| R11 | P0 | 설정: 앱별 위치·배율·감지 토글을 원자적으로 저장한다. 제작자 기본값과 사용자 변경값을 분리한다. |
| S01 | P1 | Studio: 프로젝트 생성·복제·열기·저장과 최근 프로젝트를 제공한다. 파일 직접 편집과 같은 스키마를 사용한다. |
| S02 | P1 | 편집: 리소스·애니메이션·입력 연결·제품 정보·배포 대상을 폼으로 편집한다. |
| S03 | P1 | 미리보기: 실제 앱과 같은 Runtime 규칙을 사용한다. 기본은 모의 입력, 사용자가 켜면 네이티브 전역 입력으로 검증한다. |
| S04 | P1 | GUI 빌드: Builder의 검증·진행·취소·결과를 GUI로 제공하고 별도의 빌드 로직을 만들지 않는다. |

## 5. 비기능 요구사항

아래 수치는 측정 결과가 아니라 **최초 목표값**이다. 기준 기기와 측정 방법은 [검증 전략](testing-strategy.md)에 고정한다.

| ID | 목표 |
| --- | --- |
| N01 | 기본팩 1개·설정 창 닫힘 기준, Runtime과 귀속 가능한 자식 프로세스 메모리 합계 200 MiB 이하를 목표로 한다. OS별 지표를 별도로 보고한다. |
| N02 | 애니메이션 없는 유휴 CPU 평균은 1개 논리 코어 대비 1% 이하, 기본팩 30 FPS 재생은 5% 이하를 목표로 한다. GPU·전력도 별도로 측정한다. |
| N03 | 입력 콜백 수신부터 렌더러 프레임 처리 ACK까지 p95 80 ms 이하를 목표로 한다. 이는 실제 화면 발광 지연 측정이 아니다. |
| N04 | 준비된 OS WebView 환경에서 앱 콜드 스타트부터 캐릭터 표시까지 2.5초 이하를 목표로 한다. 최초 빌드 시간은 별도 측정한다. |
| N05 | 잠금 파일과 도구체인·템플릿 버전을 기록하고 동일 입력의 논리적 빌드 재현성을 확보한다. 서명·패키지 타임스탬프까지 동일한 바이트 재현성을 보장하지는 않는다. |
| N06 | 프로젝트는 데이터만 포함한다. 임의 스크립트·셸 명령·네이티브 플러그인을 가져와 실행하지 않는다. |
| N07 | 입력 원문·입력 이력을 저장하거나 전송하지 않는다. 진단은 오류·성능·버전만 기록한다. 일반 실행에 서버 연결은 필요하지 않다. |
| N08 | 설치·실행·권한 안내를 제공하고, 공식 서명·공증 없이 가능한 범위와 OS 정책상 차단을 구분한다. |

## 6. 범위 이후

복수 캐릭터를 한 앱에 배치하는 편집기, 레이어·Live2D·3D, 자유 스크립트, 노드 그래프, 앱 내 자동 업데이트, 클라우드/원격 빌드, 스토어 등록, Linux·Windows ARM64는 초기 범위 밖이다. 한 앱에 여러 캐릭터를 띄우는 기능과 여러 독립 앱을 만드는 기능은 별도 요구사항이다.

## 7. 제품 완료 기준

- 서로 다른 두 프로젝트에서 별도 앱을 생성한다.
- 각 지원 OS의 제작 도구 없는 컴퓨터에서 다운로드·설치·권한·실행 흐름을 검증한다.
- A 앱의 위치·설정 변경이나 제거가 B 앱에 영향을 주지 않는다.
- 설정·리소스만 수정한 프로젝트에서 다른 입력 반응이 만들어진다.
- 공식 인증서·공증 자격증명 없이 릴리스 산출물이 만들어진다.
- 대상 OS별 제약, 실제 검증 여부와 미검증 항목이 릴리스 보고서에 남는다.
