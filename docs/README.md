# Desktop Buddy Studio 문서

작성·검토 기준일: 2026-11-07 (Asia/Seoul)

Desktop Buddy Studio는 **설정과 리소스로 여러 종류의 데스크톱 캐릭터 프로그램을 정의하고, 각각 독립 실행 앱으로 빌드하는 제작 도구**다. 생성된 앱은 제작 도구 없이 설치·실행되어야 한다.

## 확정된 방향

- Windows와 macOS를 지원한다.
- Tauri 2 + Rust, 화면은 TypeScript + Vite + Canvas 2D를 사용한다. 최초에는 별도 UI 프레임워크를 넣지 않는다.
- 위치·크기 조절, 전역 키보드·마우스 반응을 공통 런타임이 제공한다.
- 프로젝트마다 이름·아이콘·앱 식별자·리소스·입력 동작을 독립적으로 정의한다.
- 유료 공식 인증서와 공증을 배포의 전제 조건으로 두지 않는다. 필요한 로컬 서명·셀프 서명은 허용한다.
- OS의 미서명 앱 실행 승인과 입력 감지 권한 승인을 구분한다.
- 캐릭터 앱 포커스 없이 다른 일반 앱 작업 중 특정 키·입력 속도·키워드에 반응한다. 한글 키워드는 두벌식 물리 키 순서로 판정하며 실제 IME 텍스트를 읽지 않는다.
- 최초 지원 기준은 Windows 11 25H2 이상 x64와 macOS 15 이상 arm64다. 미검증 상태를 지원 완료로 표시하지 않는다.

## 제품을 이루는 세 부분

1. **Builder**: 프로젝트 snapshot을 검증하고 공통 런타임과 결합해 독립 앱을 빌드한다. OS별 CLI·라이브러리·자체 포함 템플릿 팩으로 먼저 제공한다. 제작자는 CLI·JSON·로컬 도구체인을 사용할 수 있어야 한다.
2. **Runtime / Player**: 생성된 앱에 포함되는 실행 엔진이다. 캐릭터 표시, 입력 반응, 위치·크기, 트레이와 사용자 설정을 담당한다.
3. **Studio**: 프로젝트 편집·미리보기·빌드를 제공하는 GUI다. 현재 로컬 웹 화면과 Node 서비스로 제공한다. [사용 안내](studio.md)를 따른다.

MVP의 핵심 증명은 **코드 변경 없이 서로 다른 두 프로젝트를 빌드하고, 제작 도구가 없는 다른 컴퓨터에서 각각 실행하는 것**이다. Studio의 풍부한 편집 기능보다 이 경로를 먼저 완성한다.

M0에서 이 경로를 최소 기능으로 먼저 시험한다. M3에서는 원래 저장소 없는 제작 환경의 CLI 빌드, 전체 P0·두 앱 동시 실행·설정 보존·배포 품질까지 통과해야 한다. 최소 패키징 성공과 MVP 완료는 구분한다.

## 문서의 상태

이 문서는 구현 기준이다. 사용자 확정 방향과 위임받아 결정한 v1 계약을 ADR로 구분했다. 현재 일부 코드와 자동 테스트·개발 앱 패키징을 구현했지만 전체 MVP와 지원 OS 실증은 완료하지 않았다. [개발 검증 기록](validation/2026-11-07-development.md)이 통과·실패·미실시 상태의 기준이다. OS 하한·화면 기술·스키마·동작·빌드 계약을 유지하며 성능 수치는 아직 목표다. 실증으로 변경이 필요하면 요구사항·ADR·스키마를 함께 갱신한다.

문서별 기준은 제품 범위·ID는 제품 요구사항, 필드·반응 충돌은 프로젝트 형식, KPS·두벌식·sequence는 입력 계약, 상태·저장·IPC는 아키텍처, 작업·산출물은 빌드·배포, 통과 여부는 검증 전략이다. 구현 계획은 이 계약의 순서와 종료 조건을 따른다.

참고 인스타그램 영상은 로그인 제한으로 세부 동작을 직접 확인하지 못했다. 요구사항은 대화에서 확인한 기능을 기준으로 한다.
